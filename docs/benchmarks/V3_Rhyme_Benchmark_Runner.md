# V3 rhyme benchmark runner — execution guide

Developer-only, no application UI, database writes, deployment or automatic AI reviews. PR #375 remains draft, based on #374. Implemented commands default to offline mode. **No paid pilot is authorized by this document.**

## What is compared

Three immutable authored Russian briefs × `current`, `a`, `a+b` × two runs = 18 jobs. The first `ru-pop-current-1` job is the pilot and counts within 18, not an extra generation.

- `current` loads the exact V3 helper from main commit `889b610b9ea41754e0389b4d9e5e53198e255dbc` with `git show`. It is not the parent branch's A+B default.
- All arms use the real `buildPrompt`, `buildAdvancedGeneratorPromptV2`, `SYSTEM_PROMPT`, `SONG_SCHEMA`, `generationOutput` and `parseSections`.
- Advanced Suno enrichment and occurrence-specific Blueprint instructions are preserved. No brief is generated by an AI.
- Only named repository declarations are compiled into isolated VM contexts, following the parent PR test strategy. The CLI never initializes privileged server modules, auth clients or a database connection.
- The real OpenAI adapter supplies the Responses body, strict schema conversion, timeout, output budget and usage normalization. Generator baseline is 8192 visible tokens; current medium reasoning gives an actual 16384 output-token cap, including reasoning. High/xhigh/max gets 32768. Installed Generator reasoning is taken from reviewed evidence, with the same null→medium fallback as runtime.

## 1. Checkout and free verification

Run from repository root, with existing dependencies and Bun 1.4.2. Git history must contain the pinned baseline commit; a shallow checkout missing it fails closed. Fetch history if necessary; do not substitute another baseline.


No API key is required for dry-run. The command neither creates a provider caller nor invokes fetch. A subprocess regression test forbids all fetch while running the real CLI with a sentinel key and checks it is absent from stdout/artifacts.

Default output: `.benchmarks.local/v3-rhyme/offline/manifest.json`. It is deterministic for unchanged source/evidence, has 18 prompt hashes, system/schema hashes, output caps, blind IDs and no full prompts or generated lyrics. The directory is already ignored by `*.local`; unlike `.output`, it survives application builds. Do not upload this directory as a CI artifact.

Without reviewed effective-registry evidence, `liveReady` is false, `effectiveModel` and `estimatedUpperUsd` are null. This is deliberate: the runner does not invent installed pricing or disguise a fallback-catalog estimate as a verified upper bound. Supplying valid evidence also allows a fully offline priced preflight:

```sh

```

## 3. One live pilot — only after separate owner authorization

Preconditions: reviewed effective-registry evidence, satisfactory offline manifest, explicit owner permission for ONE paid pilot, and `OPENAI_API_KEY` already present in the secure process environment. Never put the key in arguments, output or a committed env file. No other provider key is needed.

```sh
bun scripts/benchmarks/v3-runner.ts --live --confirm-spend-usd 3.00 --evidence .benchmarks.local/evidence.json
```

This command refuses CI, missing evidence/key and ambiguous options. It performs at most **one** paid call and stops for pilot review. A normal second invocation without the explicit continuation token refuses further requests.

Review the pilot's actual usage, estimated cost, finish status, valid song JSON, output quality and reservation before deciding whether to continue. Usage includes reasoning tokens already counted inside total output tokens; they are not billed twice by this estimator. Token usage is provider-reported; dollar amounts remain local estimates.

## 4. Remaining jobs — separately authorized after actual pilot review

Only after a second explicit owner approval, use the exact `pilotResultHash` printed after the completed pilot:


This executes remaining jobs sequentially, at most 17 after a single pilot. Completed jobs are skipped, not regenerated. After all 18 complete, repeating the same approved command performs zero calls. There are no automatic paid retries, parallel requests, Quality Checks or secondary reviewers.

## 5. Cost and failure guarantees / limits

- Budget intent is $3.00, based on user-reported $4.11 balance and intended $1.11 reserve. The balance is NOT queried or asserted as current.
- Before every dispatch, reserve full-input-window × highest applicable supplied input/cache rate plus adapter output cap × output rate. The reservation is fsynced before dispatch. If remaining allowance cannot cover it, no call starts.
- Actual usage is conservatively costed at the highest applicable input/cache rate, never relying on cache discounts; output includes reasoning. This is intentionally not an exact provider invoice.
- The sum of 18 pessimistic reservations may exceed $3 even if actual spend would fit. The manifest reports this; continuation depends on real recorded spend and the next reservation, not an assumption that all 18 are affordable.
- Missing/inconsistent usage, malformed JSON, invalid schema, truncation, provider/network/timeout failure or storage failure stops immediately. Unknown spend retains full reservation. A failed/reserved job blocks resumption pending manual billing review; it is never silently retried.
- Exclusive process lock prevents concurrent copies in this checkout. A stale lock or `.tmp` ledger after crash must be reviewed; do not delete it and rerun blindly. Completed result hashes and plan fingerprint are checked before continuing.
- Fingerprint covers fixtures, relevant source, evidence, settings and prompt hashes. Changing evidence (including refreshed timestamps), source or fixtures blocks reuse of an existing paid ledger. Complete pilot review/continuation within the evidence window, or reconcile manually rather than resetting state.
- Do not remove/reset the ledger, use another clone/output directory to bypass it, or alter evidence to bypass budget. Local checks are not tamper-proof or a cross-machine spending service.
- Provider late metering, account tariffs, billing changes and local state loss mean this is **not a provider-enforced hard financial ceiling**. Unknown applicable costs are a blocker.

## 6. Local results and blinding

Under `.benchmarks.local/v3-rhyme/live/`:

- `ledger.json`: dispatch reservations, completion/failure state, estimated charges, result hashes.
- `<blind-id>.json`: structured song, rendered lyrics, timestamp/duration, brief/arm/run mapping, model/provider, finish status, token usage including reasoning/cache categories, costs and source/prompt/schema hashes.
- `<blind-id>.failure.json`: sanitized failure metadata, usable usage when available, retained upper reservation; no raw provider error/body.
- `blind/<blind-id>.json`: only pseudonymous ID and lyrics. Share only this subset with blind creative reviewers, with consent. Mapping/source access can reveal arm identity; IDs are pseudonyms, not cryptographic concealment.

No credentials or full requests are saved. Provider errors are suppressed/sanitized; credential echoes are rejected before persistence. Local outputs may contain private/copyrighted generated text and are ignored by git. Do not commit, publish or attach them to CI artifacts by default. Windows file modes do not replace local account ACL protection.
