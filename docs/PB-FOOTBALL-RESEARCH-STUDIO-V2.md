## Quota, transport and failure behavior

Explicit source preview or already-consented analysis only. Opening the page/history, expanding existing analysis or asking the optional expert never refreshes odds. All configured statistical providers remain collected independently of the fixture picker. ESPN remains default. Odds are contextual enrichment, not a new fixture provider or automatic research.

Fixed HTTPS JoJ host/two fixed files, manual redirects rejected, bare Workers-safe fetch, streamed fatal UTF-8 JSON, **4 MB decoded byte cap** and 6-second request timeout reuse the existing bounded transport. Source-specific credential stays in headers, never browser/URL/logs. At most two sequential odds GETs per uncached enrichment; no automatic retries, no undocumented bookmaker endpoints, no `/files` discovery calls on render. Structured enrichment runs alongside odds during paid research (maximum of existing 16-second collection or 12-second odds calls, not their sum); existing Tavily/AI request bounds remain. This is a budget, not a certified hosting SLA.

Forward migration `20261105200305_football_odds_shared_quota_cache.sql` is necessary because process-local caches cannot enforce a quota across hosting isolates/restarts. It adds **only** private odds feed/cache, budget and attempt tables with RLS and no direct browser/service-role table grants. Service-only security-definer RPCs use a fixed search path, fixed file enum and shared transaction advisory lock. No user PII, API key or authentication token is stored. The reservation UUID is only a receipt identity.

Cached capture shared across users/isolates for 15 minutes; one request/file can hold a 15-minute lease. Concurrent losing processes report unavailable and do not retry/dispatch. Reserve-before-network counts errors and unknown outcomes. Hard maximum **200 reservations per UTC calendar month AND rolling 31 days**, shared across both files, bounds this application even across month rollover. Manual playground or other applications consume the same provider key but are not visible to this journal; the cap is not proof of remaining provider credit. 429/Retry-After becomes shared cooldown (at least 15m, honoring longer delays; values over 31 days fail closed indefinitely pending operational review); other failures are explicit and no stale cache is silently presented as fresh. Missing migration/DB error fails closed for odds without blocking the established analysis.

A lost claim acknowledgement causes **zero** source calls; a lost cache-write acknowledgement retains the reservation and any committed receipt. A later read can recover the shared cached payload with no new dispatch. Late old tokens cannot overwrite a newer receipt. No attempt/cost counter is fabricated or reset to release an uncertain request.

## Quotes, prompts and historical compatibility

Version-1 server-owned `bookmakerOddsSnapshot` is optional inside the existing immutable analysis JSON; no historical migration/rewrite. Exact canonical fixture, provider fixture/market/selection IDs, canonical market/line, decimal prices, per-file observation/retrieval times, source files, diagnostics. Whole market groups come from the newer file; missing groups may be supplied by the older **still-fresh** file while retaining their timestamps. Provider fixture disagreement is conflict, never first-match selection. 15-minute file freshness and strictly pre-kickoff capture are required. `updated_at` is a whole-file timestamp, **not** per-quote generation time. Missing/stale/conflicting quotes have no usable prices. Already-saved captures never change when the feed changes.

All optional source metadata echoed by the model is removed **before** schema validation and then attached only by the server. Models cannot author authoritative quotes or source receipts. The base/expert receive the same snapshot and a separately filtered current `usableBookmakerOddsSnapshot`; old captures remain historical context. No-vig normalization applies only to a complete mutually exclusive 1X2 group; double-chance probabilities are not normalized as disjoint outcomes. AI subjective percentages, market-implied/no-vig probabilities and independently calibrated probabilities remain distinct; this implementation has **no calibrated model** and does not claim validated value/ROI.

Both actual dispatch prompts use the supplied V2 overlays, alongside existing strict contracts, evidence restrictions and numerical consistency validation. No forced five picks, invented quote, source authority or guaranteed win. Expert may abstain or describe a football lean without quoted odds. New expert writes require canonical existing market IDs (encoding exact line/selection); optional offeredSelectionId must resolve to the same fresh available market in the original snapshot at dispatch. Unknown identifiers or stale/foreign references reject output after preserving observed usage. Historical free-text expert decisions remain readable; no historical rewrite. No new paid dispatch, retry or financial bypass.

Display-only reviewed Greek names extend the one existing mapper. It is used for fixtures, accessible names, previews, results/history and team history opponents. Account locale `el` enables Greek; other locales and unknown/qualified names preserve original spelling. Canonical persisted names, matching keys, outbound queries and IDs are never translated.

Compact token-styled odds panel shows only available inventory, capture timestamps, missing/stale/conflict status and uncalibrated comparisons, separate from analyst confidence. Existing FT-only settlement is reused for historical quoted selections when exact original fixture and pre-match evidence match. No new ROI/yield claim, fictional post-hoc price or unresolved push/void settlement. Missing/unsupported outcome remains null.
