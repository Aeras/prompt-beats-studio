# Global AI usage switch — production-safe contract (2026-10-25)

## Agreed behavior
Admin → AI Models: prominent toggle **Χρήση AI στην εφαρμογή** (ON/OFF), server-backed, admin-only; ON normal operations, OFF blocks **all NEW AI provider dispatches** across Generator, QC, AI Tools, Song Analyzer V1/V2, Story Map, Song Universe, Inspirations, assistant, audio revisions, background/retries/secondary judge and admin compatibility/health tests. Clear disabled messages for end users and status/admin feedback. OFF is global for all users/devices, durable across restarts, changes logged with actor/time. Default ON after migration; fail closed on inability to read policy (not fail open). Existing non-AI site works.

## Critical safety boundary
OFF must be enforced at actual provider-dispatch boundaries, not just UI or one modelCaller. Map **all** direct SDK/fetch/provider entry points and job admission/worker/retry routes before changing anything. UI alone is inadequate. Concurrency: an OFF action must order against concurrent admissions via a DB transaction/fence; provider requests admitted before OFF cannot be retroactively canceled by UI. Define precise semantics and expose in text: OFF prevents requests not yet admitted; already dispatched external calls may finish and must persist receipts/settlement. Never claim “zero active workers” from switch OFF unless tracked in-flight counts and hosting drain are separately proved. In particular PR #437 legacy provider-start RPC changes remain a distinct release coordination constraint; global toggle cannot certify or terminate old binaries automatically.

## Execution plan
One cohesive PR: audited inventory of dispatch entry points and writes; server-side durable setting and admin-only atomic RPC authorization/audit; enforce at each provider boundary and async background execution, with concurrency tests of ON/OFF ordering; admin UI toggle with pending state and stale/error recovery; disabled error UX; tests for every provider path/retry/secondary model/direct calls, deny non-admin, stale cache/DB failures, in-flight settlement, usage logs; docs/WORK-STATUS update. Exact-head Regression/Browser Quality/Database Replay green. Separate production-migration authorization and controlled publish. No real AI calls, production writes, model deletion or deployment as part of coding.

## Release dependency
Before deploying as a reliable *maintenance pause* gate, verify production version and the legacy worker drain policy separately. Do not use this new toggle to bypass verified old-worker-drain requirement for `20261025200633_precise_ai_model_uninstall_dependencies.sql`. It is a permanent product control, and can help future windows after compatible code is published and all direct dispatches are covered.
