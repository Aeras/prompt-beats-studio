## Implementation and invariants

- One inline, collapsible workspace above Advanced Generator. Setup, job controls, result, preview and evidence share page flow. Only destructive replacement/profile deletion use secondary confirmation dialogs. Collapsed workspace keeps job status, refresh/cancel/unknown controls, errors, application summary and Undo accessible. Controller remains mounted while collapsed; no effect starts paid research.
- Existing Input/Textarea/Button/Radix CompactDropdown and design tokens; scoped themed scrollbars, wrapping controls and page scrolling. English/Greek resources supply visible new copy. Custom dropdowns retain outside/Escape/keyboard dismissal and touch support. Primary outline buttons meet tested contrast rather than white-on-purple insufficient contrast.
- `planInspirationApplication` is the sole projection for seven groups: style, mood, instruments, BPM, production, instructions and atomic Arrangement (structure + Blueprint/Energy). Preview/current/proposal/next, no-op, issues, changed/destructive counts and receipt derive from it. The parent commits only changed groups, preserving untouched UI-only Custom sentinels and edit epochs. Oversized live drafts show an actionable warning rather than crashing strict preview rendering. Protected Theme, Language/variant, platform and preset metadata are never assigned by the music-only setter allowlist.
- Fill affects empty groups only. Keep and missing proposal preserve values. Add preserves original content/order; NFKC/case/whitespace equality deduplicates exact list/line equivalents. Different techniques are retained; no substring, invented synonym or semantic rewrite. Exact opposite clauses in supported English/Greek/Russian prefixes block Add; length/encoded-size overflow blocks with no truncation. BPM and Arrangement never allow Add. Arrangement preserves section identity deterministically and updates Blueprint/Energy atomically.
- Conflict detection is deliberately conservative, not a semantic proof. Arbitrary musical contradictions cannot be exhaustively recognized without editorial judgment. Free-text Add always asks the user to inspect the combined text; known opposition and length problems require Keep/Replace or editing. No new paid call resolves ambiguity.
- Apply re-reads its exact trusted job/profile ID and profile revision on the server, checks account/feature/operation epoch and displayed source, then reads the freshest Generator frame. **No await occurs between final planning/signature comparison and guarded synchronous mutation.** Confirmation binds exact source, changed-group current/next values and edit epochs. A changed comparison requires renewed confirmation; the parent commit independently compares the exact complete frame before setters execute.
- Narrow synchronous music setters record every edit, including batched A→B→A, imports/presets and external Generator paths. Selective Undo restores only receipt-owned groups whose snapshots and epochs still match. A true no-op creates no receipt, does not erase a prior Undo and does not auto-collapse. Successful change collapses and returns focus to the header.
- Active job, displayed origin and selected profile revision are distinct. Completing hidden Job B never replaces displayed Profile A. Save/Update require the explicitly displayed completed job; Rename changes metadata only. Update/Delete retain exact profile revision CAS and original server owner/entitlement checks. Refetch cannot silently adopt a newer selected revision. Account change or revoked access discards in-flight local application.
- Prompt-like proposal strings remain inert React text and user-reviewed Generator instructions; rendering/apply does not execute HTML, invoke providers or automatically generate a song. Research dispatch/accounting remains behind existing server gates and durable request IDs.
